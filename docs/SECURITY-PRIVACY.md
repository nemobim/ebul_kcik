# SECURITY-PRIVACY — 보안·개인정보 (라이트)

개인 사이드 프로젝트 기준의 가벼운 점검 메모입니다. 사용자가 작성한 고민 글을 Firestore에 저장하고 다른 사용자에게 공개하므로, 최소한의 안전장치만 정리합니다.

---

## 1. 수집·저장 데이터

| 데이터               | 위치                            | 공개 범위            |
| -------------------- | ------------------------------- | -------------------- |
| 닉네임               | localStorage, `contents.user`   | 랭킹/모아보기에 공개 |
| 고민 본문·카테고리   | `contents`                      | 모아보기에 공개      |
| 점수                 | `contents`                      | 랭킹/모아보기에 공개 |
| 임의 UUID            | localStorage, `contents.userId` | UI 비공개            |
| 공감 기록            | `userReactions`                 | UI 비공개            |

`userId`(UUID)는 브라우저에서 생성·변경 가능한 식별자이며 인증 수단이 아닙니다.

---

## 2. 최소 안전장치

### 공개 UGC 안내 (가장 중요)

고민 작성 화면에 다음을 고지합니다.

- 작성 내용과 닉네임이 다른 사용자에게 공개된다는 점
- 실명·연락처·회사/학교명 등 식별 가능한 개인정보를 쓰지 말라는 안내

### Firestore Rules 기본 확인

배포 Rules는 저장소에 없으므로 직접 확인이 필요합니다. UI/localStorage 검사는 우회 가능하므로 다음만 챙깁니다.

- 허용 컬렉션·operation 제한
- score·nickname·content 길이와 허용 필드 검증
- 기존 score/userId 임의 수정 차단

### 공감 중복 방지

현재 `getDoc → updateDoc → setDoc` 순서라 동시 요청에 취약합니다. 여유가 되면 transaction으로 묶습니다.

---

## 3. 여유 있을 때 (선택)

- 신고/숨김, 작성자 삭제 요청 경로
- 금칙어/스팸 대응
- 익명 인증(Anonymous Auth) 도입

---

> 이 문서는 가벼운 코드베이스 점검 메모이며 법률 자문이 아닙니다.
