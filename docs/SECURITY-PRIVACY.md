# SECURITY-PRIVACY — 보안, 개인정보, UGC 운영

이 앱은 사용자가 작성한 고민 글을 Firestore에 저장하고 다른 사용자에게 공개합니다. 클라이언트 코드만으로는 실제 배포 권한을 확인할 수 없으므로 운영 설정을 별도로 감사해야 합니다.

---

## 1. 현재 수집·저장 데이터

| 데이터               | 위치                            | 공개 범위            |
| -------------------- | ------------------------------- | -------------------- |
| 닉네임               | localStorage, `contents.user`   | 랭킹/모아보기에 공개 |
| 고민 본문과 카테고리 | `contents`                      | 모아보기에 공개      |
| 점수                 | `contents`                      | 랭킹/모아보기에 공개 |
| 임의 UUID            | localStorage, `contents.userId` | UI에는 숨김          |
| 공감 기록            | `userReactions`                 | UI에는 숨김          |
| 생성 시각            | `contents.createdAt`            | 정렬에 사용          |

`uniqueId`는 브라우저에서 생성·변경 가능한 식별자이며 인증 수단이 아닙니다.

---

## 2. 확인된 구조적 위험

### 2.1 Firestore Rules가 저장소에 없음

배포 Rules가 안전한지, 테스트되었는지, 환경별로 같은지 확인할 수 없습니다. UI validation과 localStorage 검사는 우회할 수 있습니다.

운영 전 최소 확인:

- 허용 컬렉션과 operation을 명시적으로 제한
- score, nickname, content 길이와 허용 필드 검증
- `worryLabel`, reaction key의 허용값 검증
- 클라이언트가 기존 score/userId를 임의 수정하지 못하게 제한
- reaction count와 reaction 기록의 원자성 보장
- 예상하지 않은 필드 추가 차단

익명 사용자를 유지할 경우 완전한 사용자 소유권 검증은 어렵습니다. Firebase Anonymous Auth 도입을 우선 검토합니다.

### 2.2 공감 중복 방지가 클라이언트 의존

현재 `getDoc → updateDoc → setDoc` 순서라 동시 요청과 부분 실패에 취약합니다. transaction과 Rules를 함께 적용해야 합니다.

### 2.3 공개 UGC 보호 장치 부족

고민 글은 민감한 개인 경험을 포함할 수 있지만 현재 다음 기능이 없습니다.

- 공개 저장 전 명확한 안내와 동의
- 개인정보 입력 금지 안내
- 신고/숨김
- 작성자 삭제 요청 또는 운영자 삭제 절차
- 금칙어/스팸 대응
- 보존 기간 정책

신고/삭제를 장기 기능으로만 두지 말고 공개 운영의 선행 조건으로 다룹니다.

### 2.4 Analytics 동의와 목적 미정

Firebase Analytics SDK는 초기화되지만 이벤트 목적, 보존, 동의 UI가 정의되지 않았습니다. 실제 수집 여부와 적용 법규를 확인하고 필요 없으면 초기화를 제거합니다.

---

## 3. 제품 문구 요구사항

고민 작성 화면에 최소한 다음을 고지합니다.

- 작성 내용이 다른 사용자에게 공개된다는 점
- 실명, 연락처, 회사/학교명 등 식별 가능한 개인정보를 쓰지 말라는 안내
- 삭제/신고 요청 방법
- 운영 정책 위반 콘텐츠가 숨김 또는 삭제될 수 있다는 점

닉네임도 공개되므로 실명 사용을 피하도록 안내합니다.
